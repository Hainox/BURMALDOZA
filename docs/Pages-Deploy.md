# Бурмалдоза — deploy demo на GitHub Pages

## Что уже подготовлено

- Статический demo-build: `docs/pages-demo/index.html`.
- GitHub Actions workflow: `.github/workflows/deploy-pages.yml`.
- В демо нет Telegram-токена, базы, платежей, авторизации, реальных денег или сохранения результатов.

## Публикация

1. GitHub Pages для `Hainox/BURMALDOZA` включён с источником **GitHub Actions**.
2. Push с изменениями в `docs/pages-demo` запускает workflow **Deploy Pages demo** автоматически; его можно запустить и вручную.
3. После успешного развёртывания пилот доступен по адресу **https://hainox.github.io/BURMALDOZA/**. Регистр пути соответствует названию репозитория.

Workflow публикует отдельную HTML-страницу, а не SvelteKit-приложение. На GitHub Pages нельзя запустить Python API или Telegram polling-бота.

## Откат

Если опубликованный пилот работает неверно, отменить только его изменения через `git revert <commit>` и запушить `main`. Workflow опубликует предыдущую версию; данные пользователей и серверные сервисы при этом не затрагиваются.

## Ручная проверка перед показом

1. Открыть URL с телефона и с desktop.
2. Убедиться, что поле ставки принимает 10–500 JG и меняет только локальное состояние страницы.
3. В рулетке выбрать «Красное» и запустить раунд: первый сценарий показывает красное и добавляет 100 JG при ставке 100 JG.
4. В блэкджеке раздать карты и нажать «Взять карту»: первый сценарий завершает раунд с локальным выигрышем; вкладки и ставка блокируются до завершения раздачи.
5. В слоте запустить первый раунд: барабаны останавливаются на «🍒 🍋 🍒» и показывают локальный проигрыш.
6. Нажать «Сбросить пилот», затем обновить страницу: баланс должен вернуться к 4 260 JG, история — к пустому состоянию.
7. Проверить, что на странице нет полей для платежей, username, Telegram-авторизации или реальных сумм.
