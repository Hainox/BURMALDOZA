# Правила Claude Code для BURMALDOZA

Общие правила проекта — источники истины, карта репозитория, команды, инварианты, роли, ветки, штаб и
формат отчёта — в [AGENTS.md](./AGENTS.md). Claude Code загружает его вместе с этим файлом
(настройка `instructionFiles: claude-md-and-agents-md`). Здесь — только то, что касается Claude Code.
Если настройка выключена, прочитай `AGENTS.md` сам перед существенной работой.

Не выводи новые продуктовые требования из черновиков, картинок или старых записей журнала. При конфликте
следуй актуальному решению владельца и явно отметь, что именно нужно согласовать.

## Роль и границы

- Роль Claude Code — read-only review, документация, тесты и небольшие задачи с точным allowlist файлов.
  Ветка — `claude/<задача>`. Domain, RNG, ledger, API-контракты, безопасность, миграции и deployment
  меняй только по задаче с явным scope и утверждённым BuildSpec.
- Не редактируй файлы, назначенные Codex или Command Code; работай в своей ветке или отдельном worktree.
- Начинай с `git status` и сохрани все изменения пользователя. Не сбрасывай, не очищай и не перезаписывай
  посторонние файлы.
- Если задача — review, работай read-only/Plan Mode: не редактируй файлы и верни только findings с точными
  путями и строками.

## Публикация

- Без отдельного запроса разрешено: push в свою ветку `claude/<задача>`, черновой PR по ней и
  отчёт-комментарий в PR или issue своей задачи (см. «Штаб» в `AGENTS.md`).
- Merge PR в `main` — разрешён по правилу «Merge силами Claude Code» в `AGENTS.md` (решение владельца
  30.09.2026); вне его условий — только с явного разрешения владельца.
- Всё остальное — новые issue вне задачи, сообщения, изменение доступа, deploy, force-push —
  только с явного разрешения владельца.

## Секреты и транскрипты

- Не включай секреты, `.env`, токены, приватные данные, реальные ключи или их значения в prompts, вывод,
  фикстуры, примеры и коммиты.
- Не открывай `.env`, credential-файлы и секретные конфигурации в сессии: Claude Code хранит prompts,
  прочитанные файлы и результаты инструментов в локальных транскриптах, а текст задания и финальный ответ
  уходят в журнал штаба. Не коммить transcript/log/cache.
- Не используй `--dangerously-skip-permissions` вне явного разрешения текущей задачи.

## Подписка и квота

- Claude Pro используется через официальный Claude Code login. `/status` — команда интерфейса: агент не
  может вызвать её сам, её проверяет владелец при запуске сессии. Агент перед работой проверяет только,
  задан ли `ANTHROPIC_API_KEY`, не печатая значение (`[ -n "$ANTHROPIC_API_KEY" ] && echo set || echo unset`);
  если `set` — остановись и сообщи владельцу.
- Модель и effort в отчёте указывай так, как они видны в контексте сессии; если не видны — «не отображается».
  Не угадывай.
- Не включай платные usage credits, API billing или auto-reload без отдельного решения владельца.
  Claude.ai и Claude Code расходуют общую квоту; не фиксируй изменяемые оценки лимитов.

## Проверка и отчёт

- Ограничивай diff указанными файлами и выполняй релевантные проектные проверки из `AGENTS.md`. Для UI
  укажи точные ручные проверки, если автоматизированного сценария недостаточно.
- Не называй проверку пройденной без фактического результата. Формат отчёта — в `AGENTS.md`.
